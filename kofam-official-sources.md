# Official-source findings for KOfam simulation plan

Checked 2026-11-12. These are planning research findings; no KEGG data or sequences were selected, no identifiers were invented, and no repository was modified.

## KEGG mappings and BRITE

- Exact KO-to-reaction endpoint: `https://rest.kegg.jp/link/rn/ko`. The [official KEGG announcement](https://www.kegg.jp/kegg/docs/announce.html) explicitly gives `/link/rn/ko` as a direct-link route (February 2016); the [API manual](https://www.kegg.jp/kegg/rest/keggapi.html) defines `link/<target_db>/<source_db>` and lists `reaction` alias `rn`, with tab-delimited output. This confirms the endpoint from official documentation, although this research tool failed to fetch its live payload. Build must still require HTTP 200, nonempty two-column KO/reaction identifiers, record retrieval timestamp, URL, hash and `info/kegg`, `info/ko`, `info/reaction` responses.
- Auxiliary BRITE hierarchy: `ko00001` is official KEGG Orthology (KO), with top-level Metabolism and other categories ([official live hierarchy](https://www.kegg.jp/kegg-bin/get_htext?htext=ko00001); [BRITE catalog](https://www.kegg.jp/kegg/brite.html)). REST route consistent with documented BRITE get/json syntax is `https://rest.kegg.jp/get/br:ko00001/json`; validate live at build time. The live hierarchy also provides an official Download json link, `https://www.kegg.jp/kegg-bin/download_htext?filedir=&format=json&htext=ko00001`, usable as an explicitly recorded official alternative. Preserve all paths per KO; do not collapse ambiguous categories silently.
- `ko01000` really is EC-based: the [official Enzymes hierarchy](https://www.kegg.jp/kegg-bin/get_htext?filedir=&hier=4&htext=ko01000) descends from EC classes (e.g. oxidoreductases) through EC numbers to KO leaves. Exclude it as the grouping key. Candidate grouping remains exactly shared reaction from ko-rn, never shared pathway/module or BRITE category.
- Biological caveat for filtering: a bare multi-KO reaction link can include subunits rather than independently interchangeable full-protein alternatives. Inspect each candidate's official KO/reaction entries at build time, reject required multisubunit components and unclear cases; this is a filter after the mandated reaction grouping, not a replacement grouping scheme. The general link API alone does not establish independent catalytic sufficiency.

## KEGG licence: distinguish access from publication rights

- [KEGG API policy](https://www.kegg.jp/kegg/rest/) limits `rest.kegg.jp` to academic use by academic users and allows at most 3 calls/second. The policy does not say ordinary academic REST access requires a signed agreement.
- [KEGG copyright page](https://www.kegg.jp/kegg/legal.html) says academic users may freely use the website; academic users providing services are requested to obtain an academic service-provider licence, included in the academic FTP subscription. KEGG is copyright Kanehisa Laboratories, not an open-licensed database.
- [Academic subscription page](https://www.pathway.jp/en/academic.html) describes paid bulk FTP/service provision and signed agreements. Current end-user option does not allow setting up a local copy; service-provider option covers research groups developing software or web services utilizing KEGG.
- Current [academic service-provider agreement, SP-202507](https://www.pathway.jp/doc/agreement_sp.pdf) grants specified research/publication/service rights while limiting redistribution of FTP data and allowing user retrieval only in small quantities. It includes subscription expiry/deletion conditions. Do not assume buying an academic subscription grants unlimited public rehosting.
- No explicit blanket permission for public redistribution of REST-retrieved raw files or derived KO/reaction/BRITE mapping tables was found. Do not present uncertain copyright scope as a definitive legal ban, or assume that converting a table to RDS, using pseudonyms, or obtaining labels via UniProt makes KEGG-derived relations open-licensed.
- Conservative workflow: download KEGG mappings at build time into a local untracked cache, preserve their hashes and version metadata, keep raw KEGG and per-protein KO/reaction/BRITE assignments private pending permission, and publish code, source URLs, parameters, software versions, aggregate simulation findings/plots and CC BY UniProt sequence/metadata material that does not expose KEGG-derived relations. A public curated RDS may contain UniProt-sourced sequences/metadata, embeddings and numerical analysis material, but inclusion of KEGG-derived labels/membership or reverse-decodable encodings needs written scope confirmation. To preserve knit-time recomputation, an authorized local/private curated RDS can be used to render the public aggregate page; public users rebuild local labels from their own authorized downloads. Do not claim this automatically resolves whether the published tooling counts as a KEGG service.
- Concrete Yixuan decision: confirm academic eligibility and ask Pathway/Kanehisa whether the planned public build tool, curated RDS with selected labels and static results page require a service-provider agreement or written redistribution permission, and which selected derived fields may be public. If FTP is used, a paid signed academic agreement is required. Use [official inquiry form linked on subscription page](https://www.pathway.jp/en/academic.html), do not contact anyone automatically.

## UniProtKB / Swiss-Prot and KO labels

- [UniProt licence](https://www.uniprot.org/help/license), with machine-readable [official help payload](https://rest.uniprot.org/help/license), applies CC BY 4.0 to all copyrightable database parts. Attribute UniProt, link licence, identify transformations, and record release/query/accession/sequence version/retrieval date/response hash. It does not grant rights in independently fetched KEGG tables.
- Current official [UniProt return-field configuration](https://rest.uniprot.org/configure/uniprotkb/result-fields) lists `xref_kegg` under genome annotation, and contains no `xref_ko` return field. Current [ID mapping configuration](https://rest.uniprot.org/configure/idmapping/fields) supports KEGG gene identifiers, not a KO target. Therefore do not assume a direct UniProt Swiss-Prot KO field exists.
- Reproducible default mapping route is Swiss-Prot accession/sequence + `xref_kegg` gene cross-reference -> KEGG REST `https://rest.kegg.jp/link/ko/<KEGG-gene-identifiers>` -> downloaded ko-rn groups. `https://rest.kegg.jp/conv/genes/uniprot:<accession>` is an API-manual-compatible fallback where necessary. Batch requests conservatively, rate-limit all KEGG calls, record unmapped and conflicting mappings, and exclude ambiguous multiple-KO proteins by fixed rule. This is already-annotated KO use and requires no KOfam HMM redistribution.
- Query/filter syntax and available fields must be validated against the build-time API schema; requests should include `reviewed:true`, taxonomic scope, fragment filter, and explicit length range. Use paginated queries or narrowly targeted requests with byte/time caps before considering a bulk Swiss-Prot download; do not invent download sizes.
